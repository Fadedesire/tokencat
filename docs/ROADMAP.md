# Роадмап TokenCat

Финальная точка: готовая программа для Windows и macOS, вход без ключей, три вида
отображения, автообновление. Опубликована на GitHub, itch.io, Gumroad/Lemon Squeezy, winget и
Homebrew. Принимает донаты или оплату «плати сколько хочешь».

Каждый шаг выполняется по команде «го следующий шаг». Блок «Промт» — это задание для Claude,
пользователю его писать не нужно. Блок «От пользователя» — что потребуется от Ромы (если пусто,
ничего). Порядок шагов можно менять, только если зависимостям это не мешает; изменения
записываются в `STATE.md`.

Рекомендуемый стек (подтверждается на S02): **Tauri 2** — Rust-ядро и UI на
TypeScript + HTML/CSS (без тяжёлого фреймворка, или Svelte). Почему: маленькие сборки,
нативный трей и строка меню, встроенный webview для входа, Rust для нативных кусков
(панель задач Windows, NSStatusItem на macOS), готовые updater и GitHub Action для сборки.
Запасной вариант — Electron: тяжелее, зато доступ к cookie webview гарантирован.

**Сквозное правило — лёгкость.** На каждом шаге думать о весе и скорости: не тащить
тяжёлые зависимости, не держать лишние процессы и таймеры, всё необязательное грузить
лениво. Бюджеты — в SPEC («Лёгкость и запуск»), отдельный шаг доводки — S13. Electron
(~80–150 МБ) в эти бюджеты не влезает, поэтому выбирается только если Tauri не справится
со входом, и это записывается в DECISIONS.md как осознанный компромисс.

## Фаза 0 — Решения и проверка подхода

### S01. Уточнить продукт
**Цель:** закрыть открытые вопросы, чтобы дальше не переделывать.
**От пользователя:** ответить на 3–4 вопроса.
**Промт:** Прочитай SPEC.md и CONTEXT.md. Задай пользователю через выбор вариантов (с
рекомендацией первой) только то, что влияет на архитектуру и бренд:
1) финальное название (предложи 4–5 вариантов без слова «Claude», первым — LimitCat);
2) что он имеет в виду под «колесом» на маке (покажи 2–3 мини-эскиза в ответе: кольцо в
   строке меню, круговой виджет на рабочем столе, другое);
3) модель денег: бесплатно + донаты / плати сколько хочешь / бесплатная + платная Pro позже;
4) языки интерфейса (RU+EN по умолчанию).
Запиши ответы в SPEC.md и DECISIONS.md. Название подставь в README.md и STATE.md.
**Готово когда:** в SPEC.md нет открытых вопросов, решения записаны.

### S02. Технический спайк: вход и данные
**Цель:** доказать на минимальном примере, что вход без ключей работает и данные приходят.
**От пользователя:** возможно, запустить установщики Rust/Node (см. S03) и один раз войти
в claude.ai в тестовом окне.
**Промт:** Сделай в `app/spike/` минимальное приложение на Tauri 2. Оно должно уметь:
(1) открыть окно `https://claude.ai/login`; (2) после входа прочитать cookie `sessionKey`
своего webview (проверь API Tauri для чтения cookie, например `cookies_for_url`, и его
поддержку на Windows WebView2 и macOS WKWebView); (3) запросить `/api/organizations` и
`/usage`, двумя способами: fetch из скрытого webview и нативный HTTP-клиент (reqwest) с cookie;
(4) вывести JSON. Зафиксируй, какой способ проходит Cloudflare через VPN пользователя. Если
у Tauri нет надёжного доступа к cookie — сделай тот же спайк на Electron и сравни.
Итог (выбранный стек и способ запросов) запиши в DECISIONS.md с аргументами.
**Готово когда:** на компьютере пользователя после входа в окне показаны реальные проценты,
решение по стеку записано.

## Фаза 1 — Ядро

### S03. Инструменты и репозиторий
**Цель:** окружение для разработки и сборки на Windows, CI для обеих ОС.
**От пользователя:** установить то, что Claude не может поставить сам (дать ссылки и
пошагово): Rust (rustup), Node.js LTS, Visual Studio Build Tools (C++), Git; создать аккаунт
GitHub (если нет) и пустой репозиторий.
**Промт:** Проверь, что установлено, и выдай пользователю короткую пошаговую инструкцию на
недостающее. Инициализируй git в `F:\LimitCat`, сделай `.gitignore`, структуру
`app/` (src-tauri, ui, shared), скрипты `dev.bat` и `build.bat` в корне, которые запускаются
двойным кликом. Настрой GitHub Actions: сборка Windows и macOS (universal) на каждый push,
артефакты сборки в Actions. Первый коммит и push.
**Готово когда:** `dev.bat` открывает пустое окно приложения, CI зелёный на обеих ОС.

### S04. Модуль входа и хранения сессии
**Промт:** Реализуй auth-модуль по выбранному на S02 способу: окно входа claude.ai, перехват
`sessionKey` после успешного входа, хранение в Credential Manager / Keychain (crate `keyring`
или аналог), чтение при старте, «Выйти» (удалить секрет и cookie webview), определение
протухшей сессии (401/403 без признаков Cloudflare). Запасной ручной ввод ключа — в
«Продвинутом», с корректной вставкой при русской раскладке. Секрет никогда не пишется в
лог и не уходит никуда, кроме claude.ai. Напиши юнит-тесты на то, что тестируется без сети.
**Готово когда:** вход → перезапуск программы → данные есть без повторного входа; «Выйти»
реально выходит.

### S05. Клиент данных и планировщик
**Промт:** Модуль usage: получение организации (сначала `lastActiveOrg`, потом список с
`capabilities: chat`), запрос `/usage`, разбор в типизированную модель с терпимостью к
новым или отсутствующим ключам. Планировщик: интервал из настроек (по умолчанию 60 с),
обновление сразу при старте, по клику и при выходе компьютера из сна; откат при 429/ошибках
(до 5 мин); пауза при отсутствии сети. Классификация ошибок по SPEC (Cloudflare/регион,
сессия, сеть, формат). Поддержка прокси из настроек. Лог в файл с ротацией (без секретов).
Тесты на разбор JSON (включая `null`-окна и незнакомые ключи) и на классификацию ошибок.
**Готово когда:** в dev-режиме данные обновляются по таймеру, ошибки показываются
правильными текстами, тесты проходят.

**От пользователя:** одобрить внешний вид или сказать, что поменять.
**Готово когда:** пользователь одобрил превью.

### S07. Вид «Поверх окон»
**Промт:** Прозрачное окно без рамки, всегда поверх (переключаемо), скругления, перетаскивание,
запоминание позиции с проверкой, что окно не оказалось за пределами экранов (мониторы

**Готово когда:** работает как прототип, но на новом стеке, и выглядит не хуже.

### S08. Онбординг первого запуска
**Промт:** Экран первого запуска по SPEC: определение ОС, две карточки вида с живыми
превью, затем вход, затем «Запускать с системой». Сохранение выбора. Повторно онбординг не

**Готово когда:** чистая установка → онбординг → выбранный вид работает.

### S09. Вид «В панели задач» (Windows)
**Промт:** Изучи и выбери способ (DECISIONS.md): (а) окно, встроенное в панель задач

значок в трее, который сам рисует проценты/мини-полоски, плюс всплывающая панель по клику.
Реализуй (а) с автоматическим переходом на (б), если встраивание не удалось. Учти светлую и
тёмную тему панели задач. Проверь на компьютере пользователя.
**Готово когда:** виджет живёт в панели задач, переживает перезапуск Проводника, клик
открывает подробности.

### S10. Вид «Строка меню» (macOS)
**Промт:** Значок в строке меню по варианту, утверждённому на S01 (рабочий: кольцо по
5-часовому лимиту + процент), шаблонное изображение для светлой и тёмной строки меню,
обновление без мерцания. Клик — поповер с подробностями и котиком. Скрыть иконку из Dock
(LSUIElement). Собери через CI; для проверки сделай в CI скриншот (или попроси пользователя
найти человека с Маком и дай ему инструкцию в 3 шага).
**Готово когда:** сборка macOS в CI зелёная, значок и поповер подтверждены скриншотом.

### S11. Настройки, трей и автозапуск
**Промт:** Окно настроек по SPEC (все пункты). Общий трей/меню-бар: Обновить, Настройки,
Вид, Поддержать проект, Выход. Автозапуск (Windows — Run-ключ реестра или плагин autostart;
macOS — Login Item). Один экземпляр. Уведомления на 80%/100% и при сбросе (выключаемые).
Переключение вида без перезапуска.
**Готово когда:** все настройки применяются сразу и переживают перезапуск.

### S12. Локализация (9 языков)
**Промт:** Вынеси все строки в файлы локалей, переведи на 9 языков из SPEC, язык по системе
(иначе EN) плюс выбор в настройках. Форматы времени («3 ч 20 м» / «3h 20m», «5 д 4 ч» / «5d 4h» и аналоги).
**Готово когда:** нет захардкоженных строк, все языки выглядят аккуратно (длинные строки
влезают).

## Фаза 3 — Качество и выпуск

### S13. Оптимизация: лёгкая, быстрая, «нажал — заработало»
**Цель:** программа весит мало, стартует мгновенно, в простое почти не тратит ресурсы и
работает с первого клика без установки чего-то ещё.
**Промт:** Замерь текущие цифры и запиши их в `docs/PERF.md` (таблица «было → стало»):
размер установщика и portable-exe, время от двойного клика до показа окна (холодный и
тёплый старт), RAM всех процессов программы (включая процессы WebView2) и CPU в простое и
во время анимации котика, сетевой трафик в час. Бюджеты — из SPEC («Лёгкость и запуск»).
Оптимизируй до попадания в бюджет:
- Сборка: release-профиль Rust (`opt-level="s"`, `lto=true`, `codegen-units=1`,
  `panic="abort"`, `strip=true`), только нужные фичи crates и плагины Tauri, без тяжёлых
  UI-фреймворков, ассеты сжаты (спрайт котика — крошечный PNG/данные в коде), шрифты —
  системные или один subset. Проверь, что UPX/упаковка не ломает подпись и не вызывает
  срабатываний антивирусов; если вызывает — не используй.
- Старт: окно показывается сразу с последними сохранёнными цифрами (кеш на диске), потом
  тихо обновляется; скрытое окно входа и всё лишнее создаются лениво, только когда нужны;
  никаких консольных окон.
- Простой: анимация котика на низкой частоте кадров (≈6–10 FPS) и полностью на паузе,
  когда окно скрыто/свернуто/экран заблокирован; таймеры «до сброса» раз в секунду без
  перерисовки всего окна; нет постоянно работающих циклов опроса.
- «Нажал — заработало»: без прав администратора, без установки Python/.NET/VC++ вручную;
  на Windows 10 без WebView2 — установщик ставит его сам (встроенный bootstrapper), на
  Windows 11 он уже есть; portable-exe запускается двойным кликом из любой папки;
  повторный запуск просто показывает уже открытую программу; после установки программа
  стартует сама и сразу ведёт к онбордингу.
Проверь на компьютере пользователя и на чистой виртуалке/Windows Sandbox (если доступна).
**Готово когда:** все цифры в `PERF.md` укладываются в бюджет SPEC, чистая установка
проходит от скачивания до лимитов на экране без единого лишнего действия.

### S14. Тестирование и QA
**Промт:** Составь `docs/QA.md` с чек-листом и пройди его: чистая установка, онбординг, все
виды, вход/выход/протухшая сессия, нет сети, VPN выключен (403), сон/пробуждение, смена

найденное. Результаты прогона — в STATE.md.
**От пользователя:** пару раз выключить/включить VPN и сеть по просьбе Claude.
**Готово когда:** чек-лист пройден, критичных багов нет.

### S15. Автообновление
**Промт:** Подключи updater (ключи подписи обновлений: сгенерируй, объясни пользователю,
где хранить приватный ключ, и положи его в GitHub Secrets — делает пользователь по
инструкции). Обновления берутся из GitHub Releases. Проверка при старте и раз в сутки,
ненавязчивое предложение обновиться.
**От пользователя:** добавить секреты в GitHub по инструкции.
**Готово когда:** версия 0.9.0 → публикуем 0.9.1 → программа сама обновилась.

### S16. Упаковка и подпись
**Промт:** Windows: установщик NSIS (или MSI) и portable-zip, иконки, метаданные. Разбери
варианты подписи кода и их цену (например Azure Trusted Signing, SignPath для open source,
обычный OV-сертификат) с учётом, что пользователь из Казахстана, и порекомендуй один. Пока
подписи нет — подготовь текст для SmartScreen («Подробнее → Выполнить в любом случае»).
macOS: dmg, universal; нотаризация требует Apple Developer Program (99 $/год) — объясни
плюсы и минусы, решение за пользователем. Настрой релизный workflow: тег `v*` → сборки →
черновик GitHub Release.
**От пользователя:** решить, платить ли за подпись Windows и Apple Developer.
**Готово когда:** тег создаёт релиз с установщиками для обеих ОС.

### S17. Бета
**Промт:** Выпусти `v0.9.0-beta`, подготовь короткое сообщение для 5–10 знакомых тестеров

Собери отзывы, раздели на «чиним до релиза» и «после», почини первую группу.
**От пользователя:** разослать сообщение тестерам, переслать отзывы.
**Готово когда:** критичные отзывы закрыты.

## Фаза 4 — Запуск и деньги
