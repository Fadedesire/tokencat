# Роадмап TokenCat (блоки)

Цель: программа для Windows и macOS, вход без ключей, три вида, автообновление; опубликована
на GitHub, itch.io, Gumroad/Lemon Squeezy, winget, Homebrew; донаты и «плати сколько хочешь».

**Как устроено.** Блок = один чат: подшаги внутри идут подряд, без нового чата и без
перечитывания доков. Если чат разросся — «Где остановились» в STATE и новый чат (см. START.md).
Блок объединяет шаги, которые трогают одни и те же файлы или одну тему, чтобы контекст
набирался один раз. S01–S07 сделаны (см. STATE). Порядок блоков можно менять, если не мешают
зависимости.

## B1. Оболочка (было S08 + S11)
**Цель:** всё «вокруг» панели: настройки, трей, автозапуск, онбординг.
**От Ромы:** проверить dev.bat в конце; ответить, если всплывёт вопрос по внешнему виду.
**Подшаги:**
1. Один экземпляр (плагин single-instance): повторный запуск показывает уже открытую программу.
   Один экземпляр — на профиль (см. п. 9), а не на всю программу.
2. Окно настроек по SPEC вместо временного `settings.html`: вид, интервал, поверх окон,
   котик, автозапуск, язык (пока список), прокси, «Выйти», продвинутое — ручной ключ,
   «Открыть лог», версия, «Поддержать» / «Сообщить о проблеме» (ссылки-заглушки).
   Всё применяется сразу и переживает перезапуск. Стиль — токены S06.
3. Трей (общий для видов): Обновить, Настройки, Вид ▸, Поддержать, Выход.
4. Автозапуск: плагин autostart (Windows — Run-ключ, macOS — Login Item).
5. Уведомления на 80 % / 100 % 5-часового лимита и при сбросе, выключаемые.
6. Переключение вида без перезапуска (пока: «Поверх окон» и заглушки под B2).
7. Онбординг первого запуска: ОС → две карточки вида с превью → вход → «Запускать с
   системой» (вкл. по умолчанию). Повторно не показывается; в настройках «Пройти заново».
8. Заодно проверить хвосты S07: нет консоли в dev, нет в Alt+Tab.
9. Несколько аккаунтов через профили (добавлено 2026-10-29 по просьбе Ромы). Сейчас вторая
   копия запустится, но покажет тот же аккаунт: ключ в хранилище, settings.json и данные
   окна входа (WebView2) общие, а вход во второй копии затрёт ключ первой.
   - Профиль = отдельные ключ (учётка keyring `tokencat-session-<профиль>`), settings.json,
     папка данных окна входа и позиция панели. Профиль по умолчанию — как сейчас, без
     миграции, чтобы уже вошедшие не вылетели.
   - Запуск второго профиля: пункт трея/меню ПКМ «Добавить аккаунт» запускает копию с
     `--profile <имя>`; свой ярлык в автозапуске для каждого профиля. Без ручных ключей запуска.
   - Имя из профиля claude.ai в шапке панели (вместо/рядом с «TokenCat»), в подсказке трея
     и в настройках. Источник имени выяснить на шаге (вероятно `/api/account` или
     `/api/bootstrap`: display_name → full_name → имя организации); запрос только при входе и
     раз в сутки, не каждый цикл. Длинное имя обрезать с «…». Почту по умолчанию не
     показывать (стримы и скриншоты).
   - Панели двух профилей не должны появляться друг на друге: вторая — со сдвигом.
**Готово когда (п. 9):** два аккаунта в двух копиях, у каждой своё имя и свои проценты; выход в
одной не трогает другую; перезапуск — обе вернулись на свои места.
**Готово когда:** чистый профиль (удалить settings.json и ключ) → онбординг → панель с
данными; настройки и трей работают и переживают перезапуск; test.bat зелёный.

## B2. Виды ОС (было S09 + S10)
**Цель:** нативные виды: панель задач Windows и строка меню macOS.
**От Ромы:** проверить вид на панели задач; Мака нет — проверка через CI.
**Подшаги:**
1. Windows — выбор способа (записать в DECISIONS): (а) окно, встроенное в панель задач

   Делаем (а) с автопереходом на (б), если встроить не удалось.
2. Клик по виджету — всплывающая панель (компонент Panel). Котик на виджете панели задач —

   строку) + текст `5ч 42% · Н 18%` / `5h 42% · W 18%`; в настройках: только 5 ч / 5 ч + неделя
   / только значок / «кольцо». Цвет по порогам. Обновление без мерцания. Клик — поповер с
   панелью и котиком. Без иконки в Dock (LSUIElement).
4. CI: сборка macOS зелёная, скриншот строки меню и поповера из CI (или инструкция знакомому
   с Маком в 3 шага).
5. Подключить оба вида к переключателю из B1 и к онбордингу.
**Готово когда:** виджет живёт в панели задач, переживает перезапуск Проводника, клик
открывает подробности; macOS-сборка зелёная, значок и поповер подтверждены скриншотом.

## B9. Ранний старт 5-часового окна + котофакт дня (идея друга Ромы, 29.10)
Делать после B2 (порядок в STATE). Перед началом блока — решения из п. 1 с Ромой.
**Суть.** 5-часовое окно начинается с первого сообщения. Если в 6:00 автоматически отправить
короткий запрос («Расскажи интересный факт про котов»), окно стартует в 6:00 и сбросится в
11:00. Сел работать в 9 — до сброса всего 2 часа: можно выработать лимит, а в 11 он уже
обновится. Пользователь задаёт не время запроса, а **время, к которому хочет сброс** (11:00) —
программа сама ставит запрос на 5 часов раньше (6:00).
**Котофакт дня.** Ответ Claude на этот запрос показываем на панели: котик «говорит» его в
облачке текста; клик по облачку или панели — закрыть до завтра.
**Подшаги:**
1. Разведка и решения (записать в DECISIONS, спросить Рому):
   - Как отправлять запрос. (а) Из TokenCat через тот же неофициальный веб-API claude.ai
     (создать чат + сообщение). Плюсы: факт сразу у нас. Минусы: компьютер должен не спать в
     это время (Windows — задача планировщика с пробуждением / macOS — `pmset`/launchd), это
     уже не «чтение лимитов», а отправка сообщений скриптом — выше риск по правилам Anthropic
     и блокировок; чат-эндпойнт сильнее защищён (Cloudflare, привязка сессии). (б) Официальные
     «запланированные задачи» Claude (claude.ai) — работают в облаке даже с выключенным ПК,
     но факт в TokenCat напрямую не попадёт, а TokenCat может только помочь их настроить
     (пошаговая инструкция). Проверить, запускает ли такая задача 5-часовое окно подписки.
   - Как округляется начало окна (с точностью до часа или до минуты) — проверить на практике
     по `resets_at`, от этого зависит подсказка «сброс будет в …».
   - Не расходует ли запрос заметную часть лимита (короткий промпт, модель Haiku/Sonnet, если
     можно выбрать), не засоряет ли список чатов (отдельный проект/удаление чата после ответа).
2. Онбординг: отдельный шаг «Ранний старт» — очень простое объяснение с картинкой-таймлайном
   (6:00 запрос → 9:00 сел работать → 11:00 сброс), переключатель (по умолчанию выкл) и выбор
   «Хочу сброс в: [11:00]» → строка «TokenCat отправит короткий запрос в 6:00». То же — в
   настройках, раздел «Ранний старт».
3. Планировщик запроса: раз в сутки в выбранное время, с учётом сна/выключенного ПК
   (пропустили — не отправлять «задним числом», если до желаемого сброса < 5 ч, просто
   сообщить), один запрос в день, без повторов при ошибке больше 1 раза; лог без текста ключа.
4. Облачко котика: компонент в components.js/css (текст до ~200 символов, перенос, хвостик к
   котику, плавное появление), показ раз в день, закрытие кликом; хранить последний факт и
   дату в settings.json профиля.
5. Тесты: расчёт времени запроса (через полночь, часовые пояса, переход на летнее время),
   «пропущено, ПК спал», одно облачко в день.
**Готово когда:** в онбординге и настройках можно включить ранний старт и выбрать время
сброса; запрос уходит в нужное время, окно сбрасывается к выбранному часу, котик показывает
факт дня в облачке и прячет его по клику.

## B3. Языки и лёгкость (было S12 + S13)
**Цель:** 9 языков и попадание в бюджеты лёгкости. Делается после B1–B2, когда весь UI готов.
**Подшаги:**
1. Все строки (UI, меню, трей, уведомления, ошибки) — в файлы локалей; 9 языков из SPEC;
   язык системы (иначе EN) + выбор в настройках. Форматы времени: «3 ч 20 м» / «3h 20m»,
   «5 д 4 ч» / «5d 4h» и аналоги. Проверить, что длинные строки влезают (DE, FR, JA).
2. Замерить и записать в `docs/PERF.md` («было → стало»): размер установщика и portable-exe,
   время до окна (холодный/тёплый старт), RAM всех процессов с WebView2, CPU в простое и с
   котиком, трафик в час.
3. Оптимизировать до бюджета SPEC: release-профиль (`opt-level="s"`, lto, codegen-units=1,
   panic=abort, strip), только нужные фичи crates/плагинов, сжатые ассеты; старт с кешем
   последних цифр на диске; окно входа и прочее — лениво; котик ≈ 6–10 FPS и пауза, когда
   окно скрыто или экран заблокирован; нет постоянных циклов опроса. UPX — только если не
   ломает подпись и не злит антивирусы.
4. «Нажал — заработало»: без админа, без ручных сред; на Windows 10 WebView2 ставит
   установщик; portable запускается из любой папки; после установки сразу онбординг.
   Проверить на чистой Windows Sandbox, если доступна.
**Готово когда:** нет захардкоженных строк, все языки аккуратны; цифры PERF.md в бюджете.

## B4. Выпуск (было S16 + S15 + S14)
**Цель:** тег → релиз с установщиками; программа обновляется сама; QA пройден.

**Подшаги:**
1. Упаковка: NSIS + portable-zip, иконки, метаданные; macOS dmg universal. Релизный workflow:
   тег `v*` → сборки → черновик GitHub Release.
2. Подпись: сравнить варианты и цену (Azure Trusted Signing, SignPath для open source,
   OV-сертификат) с учётом, что Рома из Казахстана, рекомендовать один. Пока подписи нет —
   текст для SmartScreen. Нотаризация Apple — плюсы/минусы, решает Рома.
3. Автообновление: updater Tauri, ключи подписи обновлений (сгенерировать, объяснить
   хранение приватного ключа, Рома кладёт в Secrets), источник — GitHub Releases, проверка
   при старте и раз в сутки, ненавязчивое предложение. Тест: 0.9.0 → 0.9.1 обновилась сама.
4. QA: `docs/QA.md` и прогон — чистая установка, онбординг, все виды, вход/выход/протухшая
   сессия, нет сети, VPN выключен (403), сон, смена мониторов и DPI 100/125/150 %, русская
   раскладка, сутки работы (память, CPU). Починить найденное, итог — строкой в STATE.
**Готово когда:** тег создаёт релиз для обеих ОС, автообновление сработало, критичных
багов нет.
